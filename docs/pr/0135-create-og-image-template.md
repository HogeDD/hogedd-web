# Canvaでアプリ専用OG画像を量産できるようにする

## 背景

アプリごとにOpen Graph画像を一から設計すると、制作方法と品質が担当者に依存し、公開準備のたびに同じ判断が必要になる。アプリ名、キャッチコピー、desktopとmobileの画面、HogeDDロゴを使った画像を、特定の担当者以外も作れる状態が必要だった。

## 決定したこと

- OG画像の編集にはCanvaを使う。
- 既存のCanvaデザインをHogeDDのマスターテンプレートとして流用する。
- マスターを直接編集せず、アプリごとに複製して使う。
- MacとiPhoneの画面部分へ、開発したアプリのdesktopとmobileのスクリーンショットを配置する。
- アプリごとに差し替える情報は、アプリ名、キャッチコピー、2種類のスクリーンショットを基本とする。
- 書き出しは`1200×630 px`のPNG 1枚とし、同じ画像とaltをOpen GraphとX Cardへ使用する。
- Canvaの編集元はHogeDDの共有領域で管理し、repositoryには書き出したPNGとaltだけを格納する。
- Canvaの編集URLはアクセス権を含む可能性があるため、公開repository、Issue、PRへ記載しない。
- 制作と格納の手順は`docs/guides/og-image-template.md`を正とする。

## 理由

Canvaはブラウザで利用でき、端末モックアップへの画像差し替え、共同編集、PNG書き出しを一つのツールで行える。既に作成済みのデザインを流用することで、新しい制作環境や自動生成処理を用意するより早く量産を始められる。

マスターデザインを複製して使うと、既存アプリの画像へ影響を与えず、端末配置、ロゴ、基本レイアウトを揃えられる。編集元をCanvaへ置き、実行時に必要なPNGだけをrepositoryへ置く方針は、編集ツール固有のデータをアプリケーションコードへ混ぜない現在の素材管理にも合う。

## 検討した代替案

### Penpotを使う

無料かつオープンソースで共同編集できるが、今回流用できる既存デザインがCanvaにあり、移植作業を増やす必要がないため採用しない。

### SVGテンプレートをrepositoryで管理し、自動でPNGへ変換する

再現性と自動化には優れるが、スクリーンショットのトリミングやレイアウト調整にコードまたは画像編集の知識が必要になる。誰でも視覚的に編集できることを優先し、今回は採用しない。

### アプリごとに自由なデザインを作る

各アプリの個性を強く出せるが、制作負担と品質のばらつきが増え、量産体制という目的に合わないため採用しない。

## トレードオフ

- Canvaへのアクセスとアカウントが必要になる。
- 編集元をrepositoryだけでは復元できない。
- Canvaの仕様や利用条件が変わった場合は、別ツールへの移行を検討する必要がある。
- テンプレートを統一するため、アプリごとの自由な構図には制約がある。
- スクリーンショットのトリミングと重要要素の見え方は、人が確認する必要がある。

## テスト・検証内容

- ガイドに必要素材、複製、差し替え、書き出し、格納、検証の手順が揃っていることを確認する。
- 既存の公開metadata検査が要求するPNG形式、`1200×630`、Open GraphとX Cardの一致条件と手順が一致することを確認する。
- format checkを実行する。

Canvaのデザイン内容はログインが必要なため、repositoryからは確認しない。マスターデザインの見た目と編集可否はCanvaの共有領域で人が確認する。

## 今後の見直し条件

- Canvaを利用できない参加者が制作を担当するとき。
- Canvaの利用条件、共有方法、PNG書き出し仕様が現在の運用に合わなくなったとき。
- 手作業による差し替えミスが継続し、自動生成の方が保守しやすくなったとき。
- 端末モックアップや基本レイアウトを変更するとき。
