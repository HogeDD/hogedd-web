# 0099: 手本アプリ「ララ打」を単純構成の参照実装として追加する

## 背景

#97で明文化したとおり、AIエージェント(特に小さいモデル)は原則からの導出より具体例の模倣が得意で、参照実装の有無が成果物の質を大きく左右する。しかし単純な構成(`_components` + `_lib`)の参照実装は存在せず、`app/apps/clean-tasks/`はClean Architecture構成かつ将来削除予定だった。

そこで#99で、弱いモデルが模倣して「それなりのもの」を作れる上限を示す手本アプリを追加した。題材は相談のうえローマ字タイピングゲーム(ラランド題材)。かな→ローマ字の変換表はユーザーから提供された。

## 決定したこと

- `app/apps/lala-typing/`(ララ打)を追加し、単純構成の参照実装とする。
  - `page.tsx`(入口) / `layout.tsx`(`AppPageShell` + sunsetテーマ) / `about/page.tsx` / `guide/page.tsx`
  - `_components/typing-game-client.tsx`: 唯一の`"use client"`。状態遷移は純関数`handleKey`に分離。
  - `_lib/`: 変換表(データ)、判定エンジン、スコア計算、単語リスト。すべて純関数とデータ。
  - `test/unit/apps/lala-typing/`: 41件のunit test。実装より先に作成(TDD)。
- 変換表はユーザー提供の完全展開済み生成データ(「んっきゃ」のような複合キーまで全列挙、825キー)を唯一の正とし、エンジンは「最長一致でキーを引き、入力で候補を絞り込む」だけにする。
- スマホ・タブレットは画面内ローマ字キーパッドで遊ぶ。表示の出し分けは画面幅ではなく`pointer-fine:` / `pointer-coarse:`(ポインタ精度)で行う。
- `app/apps/_lib/app-links.ts`へ`status: "preparing"`で登録する(ホームと`/apps`にカードは出ない)。
- `AGENTS.md`と`docs/guides/app-development-cycle.md`へ「参照実装を写してから作る」導線を追記する。

## 理由

- **ロジックをデータへ寄せるほど、模倣する側が壊せる箇所が減る。** 当初はエンジン内で「っ」「ん」の綴りを合成していた(約60行)が、展開済みの表に置き換えてエンジンを約25行の最長一致へ単純化した。弱いモデルはデータの差し替えはできるが、組み合わせロジックの修正は事故りやすい。
- **タッチ端末のIMEは`keydown`を信頼できない**(`key`が`Unidentified`になる、変換が割り込む等)。隠し`<input>`で実キーボードを拾う方式は機種依存バグの温床のため、自前キーパッドを採用した。タップは物理キーと同じ`handleKey`へ流れるため、エンジンに分岐が増えない。
- **ポインタ精度は「物理キーボードの有無」の近似として画面幅より正確。** iPad(画面幅は`md`以上)でもキーパッドが出て、ウィンドウを狭めたPCで誤って出ることもない。
- 重要な仕様(綴りの揺れ、っ/んの判定、ヒント追従、単語の変換可能性)はすべてテストで固定し、模倣・改変時の安全網とした。

## 検討した代替案

- **マルバツ+3段階CPU(minimax)**: 決定的で全探索テストが書ける題材として提案したが、ユーザーの希望でタイピングゲームに決定。
- **エンジン内での綴り合成(初版)**: 動作したが、ユーザー提供の展開済み変換表により不要になったため削除。データを正とする現方式の方が単純。
- **隠し`<input>`によるモバイル実キーボード入力**: IMEの挙動が機種依存のため不採用。
- **画面幅(`md:`)によるキーパッド出し分け(初版)**: タブレットで物理キーボードなしなのにキーパッドが出ない問題があり、ポインタ精度での判定に変更。

## トレードオフ

- 変換表は生142KB(gzip後 約35〜40KB)あり、このルートのbundleに乗る。ロジック削減と引き換えに許容した。表はこのルートでしか読み込まれない。
- 表を唯一の正としたため、一部の綴り(例:「んや」に`nya`)は実IMEの挙動と異なる。タイピングゲームではお題が既知のため実害はなく、必要になればデータ修正だけで直せる。
- Aboutの制作経緯は「本人の言葉はAIが代筆しない」ルールに従い仮置きのまま。公開前に人間が書く。

## テスト・検証内容

- unit test 41件(判定エンジン26・スコア11・単語4)を含む全67件が通過。
- `format:check` / `lint` / `typecheck` / `build` 通過。3ルートとも静的生成を確認。
- PC(物理キーボード)とスマホ・タブレット(キーパッド)の両方で動作確認。
