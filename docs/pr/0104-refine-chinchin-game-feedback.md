# #104 ちんちんゲームの操作と勝敗演出を整える

## 背景

#78で盤面とステータスの視覚的な優先順位は整ったが、文字を置いた瞬間、手番交代、勝敗確定の変化が静的で、操作が反映されたことやゲーム終了が伝わりにくかった。

## 決定したこと

- 置いた文字を短い拡大と回転で表示する。
- 手番や結果の文言が変わるたび、ステータスを短く立ち上げる。
- 勝利した4マスは順番に拡大しながらhighlight色で強調し、文字にはブラーをかける。
- 勝敗確定後はステータス欄に`もう一度`を表示する。
- 状態変化は`aria-live="polite"`でも通知する。
- motionはすべて`motion-safe`へ限定する。
- 音は追加しない。

## 理由

操作直後の小さな反応で入力を確認でき、勝利時だけ段階的に強調することで、通常の手番交代とゲーム終了の重要度を分けられる。文字と再戦ボタンを常に残すため、motionを無効にしても情報と操作は欠けない。

音は初期状態、音量、ミュート操作の設計が必要であり、同じ端末を2人で囲むゲームでは突然の再生が邪魔になりやすいため採用しない。

## 検討した代替案

- 紙吹雪や画面全体を覆う勝利演出。
- 勝利した文字をぼかして隠す既存表示。
- 操作音と勝利音を自動再生する。

画面全体の演出は次の操作を妨げる。勝利した4マスは色と輪郭で位置を伝えられるため、ゲームらしい見せ方として文字のブラーは維持する。自動再生は利用環境への影響が大きいため採用しなかった。

## トレードオフ

- motionを減らす設定では動きがなくなり、色と文言だけで状態を伝える。
- 音によるフィードバックはない。

## テスト・検証内容

- 状態変化がlive regionで通知されること。
- 終了後に`もう一度`が表示されること。
- motion classが`motion-safe`に限定されること。
- desktopとmobileで配置、手番交代、勝利、再戦、overflowを確認する。
- Prettier、ESLint、TypeScript、Vitest、Next.js production build。

## 今後の見直し条件

- 利用者から演出が強すぎる、または弱すぎるという反応が得られたとき。
- 明示的なサウンド設定を含むIssueを作るとき。
