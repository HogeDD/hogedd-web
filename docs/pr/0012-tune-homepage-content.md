# 0012: ホームと Apps の文言を訪問者向けに整える

## 背景

ホーム UI の大枠は整ったが、一部に実装者向け・運用者向けのメモに近い文言が残っていた。HogeDD は外部から見に来た人が最初に触れるサイトなので、内部設計や管理方針よりも「何が見られるのか」「どう遊べるのか」が伝わる状態にしたい。

## 決定したこと

- ホームの更新文言を、作品紹介として読める表現へ変更する。
- ヒーロー右側の補足情報から内部メモ感のある説明を削り、作品への導線を強くする。
- `Updates` セクションは現時点では表示しない。将来的に `Info` / お知らせとして必要になったら、同じ番号付きリスト UI を再利用する。
- `/apps` の説明カードから `app-links.ts` や DB などの実装都合を外し、Watch / Play の体験説明へ変更する。
- `/apps` の footer 説明も、動画と作品を行き来するページとして自然な文言へ変更する。

## 理由

ユーザーがサイトで最初に知りたいのは、実装の持ち方ではなく、ここで何ができるかである。内部の拡張性や運用方針は docs やコード側に残せば十分なので、公開ページでは訪問者が理解しやすい言葉を優先する。

`Updates` は UI としては良いが、今の段階では載せるべき実情報が少ない。中身が弱いまま残すより、Apps と About に集中させ、将来的にお知らせやリリース情報が増えた段階で `Info` として戻す方が自然だと判断した。

## 検討した代替案

- 文言をすべて削ってさらに余白を増やす案
  - 見た目は軽くなるが、初見の人が Apps の役割を理解しにくくなる。
- 管理方針カードを残す案
  - 開発者には便利だが、公開サイトとしては裏側の説明に寄りすぎる。
- `Updates` セクションを残す案
  - 見た目のリズムは良いが、現時点では内容が薄く、優先導線をぼかす。

## トレードオフ

- 実装や運用の意図は画面上からは薄くなる。
- その代わり、外部の訪問者には「動画を見る」「アプリを触る」という行動が伝わりやすくなる。
- Info / お知らせ用の UI は一度画面から消えるが、必要になった時点で今回の判断を踏まえて再導入する。

## テスト・検証内容

- `npm --prefix frontend run format:check`
- `npm --prefix frontend run lint`
- `npm --prefix frontend run typecheck`
- `npm --prefix frontend run build`

## 今後の見直し条件

- YouTube API や DB 連携を導入し、一覧の見せ方が変わるとき。
- 作品数が増えて、Apps ページに検索・カテゴリ・フィルタが必要になったとき。
- HogeDD の説明文やトーンをブランドとして再定義するとき。
