# 0010: ちんちんゲームにランダムオンライン対戦を追加する

## 背景

ローカル2人対戦に加えて、別端末からランダムに対戦できる導線が欲しい。将来的には永続化や WebSocket も検討できるが、まずは ngrok 越しの開発確認で成立する最小構成を作る。

## 決定したこと

- アプリの URL を `/apps/chinchin-game` から `/apps/chinchin` に変更する。
- ランダム対戦は Next.js Route Handler とサーバー内メモリで実装する。
- 1人目は待機 match を作成し、2人目が来たら同じ match に参加する。
- クライアントは polling で match 状態を取得する。
- ゲーム判定ロジックは既存の `_lib/game.ts` を共有する。

## 理由

WebSocket と永続化を最初から入れると、room 管理、再接続、スケール、掃除処理、DB 設計まで一気に増える。今回の目的は「別端末からランダム対戦できるか」を早く検証することなので、サーバー内メモリと polling で実装した。

この方式なら ngrok で同じ dev server に接続した2端末が対戦できる。オンライン対戦の UX とルールが固まったら、WebSocket や DB へ置き換える判断ができる。

## 検討した代替案

- WebSocket を使う
  - リアルタイム性は高いが、初期実装としては重いので見送った。
- DB に match を保存する
  - 再起動に強くなるが、今回は開発用MVPなので見送った。
- P2P 通信にする
  - 接続確立と NAT 対応が重いため採用しない。

## トレードオフ

- dev server 再起動で match は消える。
- 複数プロセスや serverless 環境では同じメモリを共有できない。
- polling なので完全なリアルタイムではない。
- その代わり、依存追加なしで実装でき、ngrok 越しの検証がしやすい。

## 今後の見直し条件

- 公開環境でオンライン対戦を動かす。
- 同時接続数が増える。
- 再接続、観戦、履歴、ランキングが必要になる。
- WebSocket、SSE、DB 永続化を導入する。
