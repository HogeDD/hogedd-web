# #156 Issueテンプレートを追加

## 背景

HogeDDではIssue駆動、テスト駆動、AI駆動で開発するため、Issue本文の品質がそのまま開発品質に影響する。GitHubのNew issue画面から迷わずIssueを作り始められるように、用途別のテンプレートを用意する必要があった。

## 決定したこと

- `.github/ISSUE_TEMPLATE/` にIssueテンプレートを追加した。
- Issue種別は `【app】`、`【appページ】`、`【ui】`、`【fix】`、`【確認】`、`【公開準備】`、`【youtube】`、`【マーケ】`、`【docs】`、`【test】`、`【infra】`、`【開発サイクル】` の12種類にした。
- 各テンプレートの本文は `## 背景`、`## やること`、`## やらないこと`、`## 完了条件` の4節で揃えた。
- 各節には、何を書けばよいか分かるHTMLコメントを入れた。
- `【公開準備】` には、公開完了まで `dev → main` のreleaseを止める注意書きを入れた。
- `config.yml` でblank issueを無効にし、テンプレート選択を促す。
- テンプレート構造をunit testで検査する。

## 理由

Issue Formsは必須入力やフォームUIを作れるが、作成後のIssue本文はフォームのlabelから生成される。今回は既存運用と同じ `## 背景` などのMarkdown見出しを正として揃えたいため、Markdownテンプレートを採用した。

12種類に分けたのは、タイトルの `【】` を見ただけで作業の性質が分かるようにするためである。アプリMVP、App/About/Guideページ、UI改善、不具合、確認、公開準備、YouTube、マーケティング、docs、test、infra、開発サイクルは、このリポジトリで実際に出ているIssueの粒度に近い。

特に `【app】` と `【appページ】` は分ける。`【app】` は最低限動くMVPを作るIssue、`【appページ】` はAbout/Guideや紹介文、導線などアプリ本体の外側を整えるIssueとして扱う。`【公開準備】` はProduction公開とYouTube公開の両方を確認するまで閉じないため、通常の実装Issueとも分ける。

## 検討した代替案

- Issue Formsにする案: 入力欄を必須にできる利点はあるが、本文の4節をMarkdownとして揃える目的とずれるため採用しなかった。
- テンプレートを1つだけにする案: 迷いは少ないが、タイトルprefixや書くべき観点が曖昧になるため採用しなかった。
- さらに細かくrelease PR専用、依存更新専用、設計相談専用テンプレートを作る案: 既存Issueの実例が少なく、初手として選択肢が増えすぎるため見送った。

## トレードオフ

- Markdownテンプレートなので、GitHub側で各欄を必須入力にはできない。
- blank issueを無効にするため、想定外のIssueでも近いテンプレートを選ぶ必要がある。

## テスト・検証内容

- `test/unit/github/issue-templates.test.ts` で、blank issue無効化、title prefix、4節構成を確認する。
