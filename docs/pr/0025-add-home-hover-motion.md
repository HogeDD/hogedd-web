# ホームに軽いhover motionを追加する

## 背景

ホーム画面は静的な印象があり、リンクやボタンへマウスを重ねても操作可能な要素だと分かりにくかった。一方で、スクロールや読み込み時の演出を増やすと、コンテンツの閲覧を邪魔する可能性がある。

## 決定したこと

- 明確なボタンは、hover時に色、影、位置を控えめに変化させる。
- HeaderとFooterの文字リンクは、位置を動かさず色だけ変化させる。
- アプリカードはボタンより強く、12px浮かせて影を深くする。
- 公開済みアプリのサムネイルは、カードのhover時にわずかに拡大する。
- カード上部に動作領域を確保し、浮き上がった際の見切れを防ぐ。
- `prefers-reduced-motion`が有効な環境では、位置移動とサムネイル拡大を行わない。
- スクロールや読み込みに連動するmotionは追加しない。

## 理由

ボタンの小さな浮き上がりは操作可能であることを伝え、カードの12pxの移動はコンテンツ単位を選択している感覚を明確にする。カードは面積が大きいため、ボタンと同じ移動量では変化が分かりにくい。

色や影は残しつつ移動と拡大だけを`motion-safe`へ限定することで、動きを減らす端末設定を尊重しながら操作状態を伝えられる。

## 検討した代替案

### スクロールや読み込み時にも動かす

画面全体の印象は強くなるが、情報を読む動作へ干渉するため今回は採用しない。

### すべてのリンクを浮かせる

HeaderやFooterまで動くと画面が落ち着かず、要素ごとの重要度も分かりにくくなるため採用しない。

### カードの移動量を小さくする

6px程度ではカードの大きさに対して変化が弱かった。見切れ対策を行ったうえで12pxを採用する。

## トレードオフ

- hoverできないタッチ端末では、今回の視覚効果はほとんど現れない。
- カード上部へ動作領域を追加するため、カルーセル内部に余白が必要になる。
- motionの強さを変更する場合は、見切れ防止用の余白も合わせて調整する必要がある。

## テスト・検証内容

- Prettierによるformat確認。
- ESLintによる静的解析。
- TypeScriptの型チェック。
- Vitestのunit test。
- Next.jsのproduction build。

## 今後の見直し条件

- タッチ端末向けの操作フィードバックを追加するとき。
- ホーム全体のmotion方針を改めて検討するとき。
