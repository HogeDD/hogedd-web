# ニシ打の出題文を企画に合わせる

## 背景

`lala-typing`を「ニシ打」へ改名した後も、出題データは参照実装で使っていた一般的なラランド関連語彙のままだった。ニシ打の企画意図は、ニシダに向けられたコメントをタイピングする体験にあるため、公開前に問題文を企画へ合わせる必要があった。

## 決定したこと

- Issue #126のコメントで人間が提示した文面を、そのまま`display`へ登録する。
- AIがコメント本文を追加・補完・言い換えしない。
- タイピング判定用の`reading`は、各文面に対応するひらがなの読みとして登録する。
- 全ての読みが既存のローマ字変換表で処理できることをunit testで確認する。
- 長文を表示しても崩れにくいよう、出題文の表示サイズを少し抑え、折り返しを許可する。

## 理由

本人や相方が読む前提の文面は、AIが推測して作るべきではない。Issue上で人間が確認した文面を固定し、テストで差し替わりや欠落に気づけるようにする方が、企画意図と運用ルールの両方に合う。

既存のタイピングエンジンとスコア計算は、読みがローマ字変換可能であればそのまま使える。今回の目的は問題文の差し替えであり、入力判定や採点の挙動を変える必要はない。

## 検討した代替案

### AIが似た文面を追加する

問題数を増やせるが、Issueの「やらないこと」に反し、本人に向けた言葉をAIが代筆することになるため採用しない。

### 表示文から読みを自動生成する

変換漏れを減らせる可能性はあるが、漢字、数字、記号、口語の読みを人間の意図どおりに扱える保証がない。今回は人間確認済みの読みを明示する。

### タイピングエンジンを変更して記号や数字を直接入力対象にする

表示文に近い入力体験にできるが、今回の範囲は問題文の差し替えであり、入力判定の仕様変更は不要なため採用しない。

## トレードオフ

- 表示文と読みを手で対応させるため、読みの確認が必要になる。
- 長文表示に合わせて文字サイズを抑えたため、短文だけを出す場合より迫力は少し下がる。
- 記号や数字は表示文に残しつつ、読みではひらがなへ変換するため、完全な逐字入力ではない。

## テスト・検証内容

- Issueで確認された文面が`typingWords`へ登録されていることをunit testで確認する。
- 全ての読みが`buildUnits`でローマ字入力単位へ変換できることを確認する。
- `pickWords`が重複なしで出題できることを確認する。
- desktop幅とmobile幅でニシ打を開き、長文の出題文、読み、ローマ字表示に横スクロールが出ないことを確認する。
- `npm run format:check`
- `npm run lint`
- `npm run typecheck`
- `npm test`
- `npm run build`

## 今後の見直し条件

- 人間が文面を追加、削除、修正するとき。
- 読みの揺れを別の入力として許可したくなったとき。
- 長文表示が実機で読みづらいと分かったとき。
