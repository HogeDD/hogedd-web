# 画像や素材の管理ルールを決める

## 背景

ホームやアプリ紹介で画像を使う機会が増え、アプリ専用画像、公開URLが必要な画像、Next.jsのMetadata画像を同じ場所へ置くと、所有する機能とフレームワーク規約の両方が分かりにくくなる。

共同開発者から素材を受け取る際に、サイズ、形式、権利情報の基準もなかった。

## 決定したこと

- importして使うアプリ専用画像は`app/apps/<app-name>/_assets/`へ置く。
- 公開URLが必要なアプリ専用画像だけ`public/apps/<app-name>/`へ置く。
- OG画像やiconはNext.jsのfile conventionを優先し、対象route segmentへ置く。
- アプリ代表画像は16:9の`1280×720`、OG画像は`1200×630`を受け渡しの基準とする。
- ファイル名は半角英小文字、数字、ハイフンによる`kebab-case`とする。
- 自作以外の素材は、出典、作者、ライセンス、attribution、加工内容をPR本文へ記載する。

## 理由

アプリ専用コードと素材を近くに置くことで、機能を変更または削除するときに影響範囲を追いやすい。static importできる画像はNext.jsが寸法を取得できるため、レイアウトシフトも防ぎやすい。

一方、CSSや外部参照で固定URLが必要な画像は`public/`が適している。用途によって置き場所を分け、すべての画像を一つの共有フォルダへ集めない。

## 検討した代替案

### すべて`public/images/`へ置く

参照方法は統一できるが、アプリの所有境界が失われ、未使用画像の判断も難しくなるため採用しない。

### すべて各アプリの`_assets/`へ置く

コンポーネントから使う画像には適しているが、公開URLが必要な用途やNext.jsのMetadata file conventionには合わないため採用しない。

### 元画像と編集データをすべてrepositoryへ残す

再編集はしやすいが、容量が増え、アプリの実行に不要なバイナリ管理が必要になる。必要になった段階で外部ストレージを検討する。

## トレードオフ

- 画像の用途を判断してから置き場所を選ぶ必要がある。
- 同じアプリの素材が`_assets/`、`public/apps/`、route segmentに分かれる場合がある。
- PR本文の出典情報は自動検証できないため、reviewで確認する必要がある。

## テスト・検証内容

- Next.js 16.2.6のlocal docsでstatic image import、`public` folder、Metadata file conventionを確認。
- PrettierでMarkdownのformatを確認。

## 今後の見直し条件

- 画像の数やrepository容量が大きく増えたとき。
- CMS、object storage、画像CDNを導入するとき。
- 複数アプリで同じ素材を実際に再利用するようになったとき。
- ライセンス情報をPR本文だけで追跡しにくくなったとき。
