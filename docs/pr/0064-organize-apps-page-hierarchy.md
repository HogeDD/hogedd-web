# Appsページ全体の視覚階層を整える

## 背景

Appsカードの情報を整理した後も、ページ上部には長い導入文とWatch / Playの説明カードが残っていた。見出し、説明カード、アプリ一覧が同じ強さで並び、ページの主役であるアプリ一覧へ視線が届きにくかった。

また、Headerがページ幅のcontainer内に置かれていたため、ホームと下線の見え方が異なっていた。

## 決定したこと

- Headerをホームと同じくコンテンツcontainerの外へ置く。
- Watch / Playの説明カードを削除する。
- ページ冒頭の文字は大きな`Apps`だけにする。
- ホームと同じ円や線の装飾を使い、説明文ではなく背景と余白で視線を誘導する。
- おすすめは濃緑の背景面として強調し、slug配列で人力管理する。
- 一覧は明るい背景面へ全公開アプリを自動表示し、おすすめより淡い円と線を添える。
- おすすめカードと一覧カードは同じコンポーネントを使い、内容差が出ないようにする。
- おすすめカードはdesktop最大23remの強調サイズとする。
- 一覧カードはdesktopで3列にし、サムネイル、○○DD、タイトルだけを表示する。
- 一覧カードのサムネイルをYouTubeへのリンクとし、ボタンを置かない。
- 一覧カードはサムネイルの16:9表示を維持し、情報欄の余白と文字を抑えて一画面の表示件数を優先する。
- 一覧カードはホームのカードと同様に、hover時に上へ移動して影を強める。

## 理由

ページ上部の説明をなくし、文字ではなく面の色、装飾、余白でおすすめと一覧の役割を伝える。これにより、訪問者が説明を読まなくてもカードへ視線を移せる。

おすすめの内容は運用者が人力で変更する可能性が高い。ページのJSXへ条件を追加するのではなく、slugを一つの設定へ集約することで変更箇所を限定する。一覧は全公開アプリを自動表示し、掲載漏れを防ぐ。

## 検討した代替案

### Watch / Playを小さく残す

動画とアプリの二つの導線は説明できるが、カード自体に両方のボタンがあり、ページ上部で繰り返す必要がないため採用しない。

### 見出しと導入文でページの役割を説明する

意味は伝わりやすいが、文字量が増え、一覧を見る前の負担になる。`Apps`、おすすめ、一覧という最低限の見出しだけを残す。

### おすすめだけを表示する

現在は公開アプリが一つなので重複を避けられるが、すべての公開アプリを探せる入口がなくなる。おすすめと全件一覧は役割が異なるため、同じアプリが含まれても両方を表示する。

## トレードオフ

- 公開済みアプリは一覧へ自動表示されるが、おすすめに載せる場合はslug設定の変更が必要になる。
- slugの入力を誤るとbuild時にエラーになる。
- おすすめと一覧に同じアプリが表示される。
- 装飾を増やしすぎるとカードより背景が強くなるため、円と線だけに限定する。

## テスト・検証内容

- おすすめ設定と全公開アプリ一覧をunit testで確認する。
- Prettier、ESLint、TypeScript、Vitest、Next.js production build。
- desktopとmobileでHeaderの下線、余白、一覧の幅、overflowを確認する。
