# アプリ内ナビと戻る導線を共通化する

## 背景

App、About、Guideを全アプリ共通のページ構成としたため、ユーザーがアプリごとに移動方法を学び直さずに済む共通ナビが必要になった。また、Apps一覧へ戻る導線はアプリ内移動と役割が異なるため、分けて表示する必要がある。

## 決定したこと

- アプリ内ナビの表記を`App / About / Guide`で統一する。
- 現在地は濃緑の`accent`背景と白文字で強調する。
- Apps一覧へ戻る導線は`← Apps`として、アプリ内ナビの外に置く。
- 各アプリのlayoutから、アプリ名、route、利用可能なページを共通shellへ渡す。
- 未実装のAboutとGuideはリンクにせず、薄い準備中表示にする。
- AboutまたはGuideのroute追加時に、利用可能なページへ加えるだけでリンクを有効化できる構成にする。

## 理由

現在地を明確にしながら、サイト全体へ戻る操作とアプリ内の移動を混同させないためである。存在しないrouteへのリンクを先に表示すると404へ誘導するため、後続Issueでページが実装されるまではラベルだけを表示する。

濃緑、黄色、淡い緑を比較し、HogeDDのブランド色と選択状態の視認性が最も両立する濃緑を採用した。

## 検討した代替案

### 黄色で現在地を表示する

目立ちやすいが、ナビ全体の中で強く見えすぎるため採用しない。

### 淡い緑で現在地を表示する

周囲には馴染むが、選択状態として弱く見えるため採用しない。

### 未実装ページにもリンクする

後続ページのURLを先に示せるが、ユーザーを404へ誘導するため採用しない。

### Apps一覧への導線を3項目の中へ含める

表示は小さくまとまるが、アプリ内ページと一覧へ戻る操作の階層が分かりにくくなるため採用しない。

## トレードオフ

- AboutとGuideが実装されるまでは、操作できない項目がナビに表示される。
- routeを追加した際は、各アプリlayoutの利用可能ページも更新する必要がある。
- 現在地判定に必要な小さなClient Componentが追加される。

## テスト・検証内容

- App、About、GuideのURL生成と現在地判定をunit testで確認した。
- desktopとmobileでナビの幅、overflow、現在地表示を確認した。
- Clean Tasksとちんちんゲームの両方で共通ナビとApps一覧への導線を確認した。
- 未実装のAboutとGuideがリンクにならないことを確認した。
- browser consoleにerrorとwarningがないことを確認した。
- Prettier、ESLint、TypeScript、Vitest、Next.js production build。

## 今後の見直し条件

- AboutとGuideを実装し、3ページ間を実際に移動したとき。
- アプリテーマを共通ナビへ適用するとき。
- アプリ数が増え、layoutごとの利用可能ページ指定が重複すると分かったとき。
