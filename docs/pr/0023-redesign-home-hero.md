# 0023: ホームのヒーローをブランドコピー主役に再設計する

## 背景

#17 では、ホーム画面を文字に頼りすぎず、ビジュアルと余白で伝える方向にしたいという方針が出ていた。#22 では HogeDD のブランドコピーも整理されたため、ホームの最初の画面にその方針を反映する。

## 決定したこと

- hero の主役を `Hoge Driven Development` にする。
- サブコピーとして `人は欲望によって進歩する。` を表示する。
- `その衝動には価値がある。`、`理由はそれで十分だ。`、`モテたい。楽をしたい。やってみたい。` は今回の hero から外す。
- 右側の featured app カードを、文字を入れない幾何学ビジュアルパネルへ変更する。
- Three.js は今回の hero では採用しない。
- About の文言からネガティブ寄りの表現を避け、#22 のブランド方針に寄せる。

## 理由

ホームの hero は、説明を読む場所ではなく、HogeDD の印象を最初に伝える場所にしたい。そこで、アプリ説明カードを主役にするのではなく、ブランドコピーと大きな視覚要素を前面に出した。

ただし、コピーを重ねすぎると最初の印象が説明的になりすぎる。追加コピーはブランドガイドには残しつつ、hero では `人は欲望によって進歩する。` までに絞った。

右側には文字を入れない幾何学ビジュアルパネルを入れた。コードや説明文を読ませるより、HogeDD の空気感が最初に伝わることを優先した。作品への導線は featured app のタイトルとボタンとして残す。

Three.js で MacBook 風の 3D 表現も試したが、手組みの簡易モデルではハリボテ感が強く、現時点のサイト品質に合わなかった。リアルなPC表現が必要なら、Three.js で無理に作るより、実写・生成画像・きちんと作った3D assetのいずれかを使う方がよい。

開発画面風のパネルも試したが、何が書いてあるかに意識が寄りすぎて、ホーム hero のビジュアルとしては説明的だった。今回はユーザーにとって開発中であることを伝えるより、コンテンツ集約サイトとしての印象を作ることを優先する。右側のパネルは、左側のコピーを補足する文章ではなく、見た目の強さを作るための要素として扱う。

## 検討した代替案

- 現在の featured app カードを維持する案
  - アプリへの導線は分かりやすいが、ブランドコピーの印象が弱い。
- サムネイルを大きく全面に出す案
  - ビジュアルは強いが、HogeDD のコンセプトより個別アプリが主役になりすぎる。
- static な H/D/D タイルを置く案
  - 軽く実装できるが、ブランドロゴの分解に寄りすぎて、`impulse` の雰囲気が弱かった。
- Three.js で MacBook 風の 3D を作る案
  - 動きは出せるが、リアルに寄せるほど質感の不足が目立ったため見送った。
- 開発画面風のパネルにする案
  - コンセプトは伝わるが、コードを読ませる方向に寄りすぎた。
- 文字入りのブランドポスターにする案
  - 情報は増えるが、左側の hero コピーと役割が重なる。
- コピーを増やしてコンセプトを説明する案
  - 意図は伝わるが、ホームの第一印象が少し重くなる。

## トレードオフ

- featured app の説明量は減る。
- その代わり、hero の第一印象はブランド寄りに強くなる。
- Three.js の動きはなくなる。
- その代わり、依存関係とクライアント側の描画コストを増やさず、見た目の破綻を避けられる。
- 個別アプリの詳細導線は Apps セクションへ寄せる。

## テスト・検証内容

- `npm --prefix frontend run format:check`
- `npm --prefix frontend run lint`
- `npm --prefix frontend run typecheck`
- `npm --prefix frontend run build`
- ローカルブラウザで hero の表示、不要コピーの非表示、文字なし幾何学パネルの表示を確認する。
