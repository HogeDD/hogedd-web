# 0022: HogeDD のブランドコピー方針を整理する

## 背景

#17 のホーム画面整理から、#22 として HogeDD のコンセプトと言葉を整理する必要が出てきた。ホームの UI を作る前に、何を主役にして、どの言葉を避けるかを明確にしておきたい。

## 決定したこと

- `docs/guides/brand-copy.md` を追加する。
- メインコピーは `Hoge Driven Development` とする。
- サブコピーは `人は欲望によって進歩する` とする。
- サードコピーは `その衝動には価値がある` とする。
- 長めのコピー候補として `モテたい。楽をしたい。やってみたい。理由はそれで十分だ。` を残す。
- ブランディングでは `クソアプリ`、`クソゲー` などのネガティブ語を避ける。

## 理由

HogeDD は、軽い動機や個人的な欲望を開発のきっかけとして肯定する。だからこそ、言葉は雑に自分たちの作ったものを下げる方向ではなく、衝動に価値があることを伝える方向に寄せる。

ホーム画面では文字量を増やしすぎず、短いコピー、余白、ビジュアルで伝える方針にしたい。そのため、hero やアプリ紹介で使う言葉の軸を先に決めた。

## 検討した代替案

- Issue コメントだけに残す案
  - 履歴としては残るが、実装時に参照しにくい。
- すぐにホーム UI へ反映する案
  - 早く見た目に出せるが、#23 のヒーロー再設計と混ざる。
- ネガティブ語もユーモアとして使う案
  - 目立つが、ブランドとしての前向きさが弱くなる。

## トレードオフ

- コピーを guide に固定すると、あとから変えるときに docs 更新が必要になる。
- ただし、実装 Issue ごとに言葉がぶれるより、現時点の軸を残す方がよい。
- ホームへの実反映は #23 以降に分けるため、この PR だけでは画面は変わらない。

## テスト・検証内容

- `npm --prefix frontend run format:check`

- アプリ紹介文にネガティブ語やばらつきが出てきたとき。
- HogeDD の思想やブランドトーンをさらに整理するとき。
