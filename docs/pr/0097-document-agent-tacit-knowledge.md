# 0097: AIエージェント向けの暗黙知をAGENTS.mdへ明文化する

## 背景

これまでのdocsは「何があるか(What)」と「なぜ決めたか(Why)」を厚く残してきたが、過去のセッションでAIエージェントが試行錯誤や失敗を通じて獲得した暗黙知——運用上の落とし穴、やってはいけないこと(負の知識)、ハウススタイルの具体トークン、オーサリング規約——は、常にコンテキストへ乗る`AGENTS.md`にも、いずれのdocsにも明文化されていなかった。

このため、初対面のAIエージェントは既存の参加者と同じ精度で動けず、「`Closes #N`を書けば自動closeされる」「`next.config.ts`に画像ホストを足す」「`prose`クラスを使う」など、このリポジトリでは誤りになる判断を再発明するおそれがあった。

今後さまざまな人がAIを使ってこのリポジトリへ参加するため、持続性・拡張性・自己修復力のある共通理解を`AGENTS.md`へ集約する。

## 決定したこと

`AGENTS.md`へ次を追加した。

1. **ドキュメント索引**: 作業内容ごとに「いつどのdocsを読むか」の対応表。docsの中身は複製しない。
2. **既知のハマりどころ**: `dev`へのmergeではIssueが自動closeされない(default branchが`main`のため)、エージェントのdev serverは3000番と同時起動できない、`next.config.ts`を画像のために汚さない、`prose`は無効、About/Guideの本文をAIが代筆しない、など実際に発生した事象のみを記載。
3. **アプリページのハウススタイル(具体トークン)**: テーマCSS変数、コンテンツ幅、見出し・節ラベルのclass、罫線を使わず背景色でリズムを作る、装飾円の付け方など。「`AppAboutShell`/`AppGuideShell`を正とし、トークンはそれに合わせて手書きする場合の指針」と位置づけた。
4. **このファイル自体の運用**: 自己修復ルールとして、(a)現実とこのファイルが食い違ったら現実を正としこのファイルを直すPR/Issueを残す、(b)明文化されていない問題にぶつかったら解決後に「既知のハマりどころ」への追記を提案する、(c)新しい知識の置き場所(このファイル/`docs/guides/`/decision log)の判断基準、(d)節が育ちすぎたら`docs/guides/`へ切り出す、(e)推測を書かず確認した挙動だけを書く、を定めた。
5. 「変更後」チェックリストへ「明文化されていないハマりどころにぶつかったなら、追記を提案したか」を追加し、(b)を毎回の手順へ配線した。

## 理由

- 文書1層だけで「どのAIエージェントが来ても同じ仕事ができる」状態を保証することはできない。重要なルールほど型・lint・CIという機械的な層、または`app/apps/clean-tasks/`のような実行可能な参照実装へ移し、`AGENTS.md`は入口(索引)と過去の失敗の記録に専念させる方が壊れにくい。
- 「ハマったら明文化する」を個人の善意に依存させると、知見が記録される保証がない。チェックリストに組み込むことで、再発防止のコストを継続的に下げる仕組みにした。
- 推測ではなく実際にぶつかった事象だけを書く方針にすることで、内容の陳腐化(現実と乖離した規範が居座ること)を防ぐ。
- ハウススタイルを「具体トークンの羅列」ではなく「shellのコードを正とし、トークンはその要約」と位置づけることで、shell実装が進化してもAGENTS.mdが古い指針を強制し続けない。

## 検討した代替案

- **4種類を別Issueに分けて段階的に進める**: 確実だが、関連する4つの知識(運用/禁止/トークン/規約)が別々のPRになり、相互参照や一貫性の確認が分散する。今回は「持続性と拡張性のある環境を今ここで作る」という要望のもと、関連性の高い4種類を1Issue・1PRにまとめることを選んだ。
- **既存docsの内容をAGENTS.mdへ大量に複製する**: 重複によりどちらが正か分からなくなり、将来の更新で食い違いが生じる。索引化+参照実装/型での担保を優先し、複製は避けた。
- **「このファイル自体の運用」を別の独立したdocsファイルにする**: メタルールが本体から分離すると参照されにくくなるため、`AGENTS.md`内の1セクションとして統合した。

## トレードオフ

- `AGENTS.md`は84行増加した。長期的には肥大化のリスクがあるため、今回「節が育ちすぎたら`docs/guides/`へ切り出す」という判断基準も同時に追加し、将来の分割を妨げないようにした。
- 「現実とこのファイルが食い違ったら現実を正とする」と明記したことで、`AGENTS.md`の権威は相対的に下がるが、陳腐化したルールに縛られて誤った判断をするリスクを下げられる。
- ハウススタイルのトークン(class名など)は、shell実装が変わると追従が必要になる。これは許容し、shellのコードを一次情報として明記することで対応する。

## テスト・検証内容

- `npm run format` / `npm run format:check`: 通過。
- `npm run lint`: 通過。
- `npm run typecheck`: 通過。
- コード変更を伴わないため、`npm test` / `npm run build`は対象外。

## 今後の見直し条件

- 「既知のハマりどころ」がカテゴリ横断で増えすぎたら、トピック別に`docs/guides/`へ切り出し、索引から参照する形へ移行する。
- 散文で書いたルールのうち、繰り返し違反が発生するものは、lintルールや型での強制を検討する。
- 次回以降のアプリ追加・ページ追加で、新しいAIエージェントが`AGENTS.md`からどこまで自走できたか/どこで止まったかを観察し、ギャップがあれば追記する。
