# 0007: YouTube 紹介リンクを静的データで管理する

## 背景

HogeDD で作ったアプリは YouTube で紹介し、概要欄から `/apps` 配下のページへ誘導したい。最初の運用では更新頻度が高くないため、DB や YouTube API 連携を先に入れるより、コード上のデータ追加だけで更新できる形を優先する。

## 決定したこと

- `/apps` を YouTube 紹介動画リンク集として扱う。
- YouTube URL は `frontend/app/apps/_lib/app-links.ts` に静的データとして追加する。
- YouTube URL の解析は `frontend/app/apps/_lib/youtube.ts` に分ける。
- 現時点では YouTube Data API と DB は導入しない。

## 理由

運用者が自分だけで、更新頻度も低い段階では、DB を入れると管理画面、認証、migration、公開状態、バックアップまで責務が増える。まずは静的データで十分に回せる。

一方で、YouTube URL の解析をページに直書きすると後から API 連携へ移しにくい。そのため、表示ページ、静的データ、YouTube URL 解析を分けた。

## 検討した代替案

- DB で管理する
  - 今は運用コストが重いので見送った。
- YouTube Data API と連携する
  - 将来的にはタイトル、サムネイル、再生数などを取れて有用。ただし API key と quota 管理が必要なので初期段階では見送った。
- Markdown で管理する
  - 本文を厚く書く段階では有効。今はリンク集が主目的なので TypeScript の配列を優先した。

## トレードオフ

- 更新には PR が必要になる。
- YouTube のタイトルや再生数は自動同期されない。
- 代わりに、CI と型チェックで壊れた URL 形式や表示差分に気づきやすい。

## 今後の見直し条件

- 更新頻度が高くなる。
- 管理画面から追加したくなる。
- YouTube のメトリクスを見せたくなる。
- 公開予約、タグ検索、並び替えなどの運用要件が増える。
