# Appsカードの表示情報と導線を整理する

## 背景

`/apps`のカードには、サムネイル、公開状態、日付、説明、タグ、アプリ導線、YouTube導線、X共有が並び、商品棚としてアプリ名と主要導線を見つけにくかった。

また、動画準備中のアプリも一覧とホームへ表示されていたが、紹介動画が完成してから公開する運用へ変更することになった。

## 決定したこと

- AppsカードはYouTubeサムネイル、タイトル、○○DD、アプリ導線、YouTube導線だけを表示する。
- ○○DDは、そのアプリが何に駆動されて開発されたかを示す情報とする。
- 「アプリを見る」を主要導線、YouTubeを補助導線として見た目を分ける。
- 紹介動画が公開済みのアプリだけ、ホームと`/apps`へ表示する。
- Clean Tasksの○○DDは「学習DD」とする。
- Clean Tasksは現在の表示確認用として一時的に残し、本格的なアプリ公開を始めるときに一覧から削除する。
- 最初の正式公開アプリは、ちんちんゲームを予定する。

## 理由

カードの役割は、アプリを選んで本体または紹介動画へ進むことにある。YouTubeサムネイルはアプリと動画を識別する画像として残し、日付、タグ、説明、共有ボタンを外す。タイトルと開発動機を短く見せることで、アプリ固有の印象と操作の優先順位を明確にする。

準備中カードを公開しないことで、利用できると誤認する入口を作らず、紹介動画とアプリを同時に公開する運用へ揃えられる。

## 検討した代替案

### 準備中カードを残す

今後の公開予定は伝えられるが、商品棚として選択できない項目が混ざり、利用者にとっての一覧性が下がるため採用しない。

### 説明とタグを残す

技術情報は伝えられるが、カード内の文字量が増え、タイトルと主要導線が弱くなる。必要になった場合は個別アプリページで扱う。

### X共有をカードへ残す

共有はできるが、アプリを開く目的と動画を見る目的より優先度が低い。カードの常設導線からは外す。

## トレードオフ

- カードだけではアプリの詳細や使用技術が分からない。
- 動画が完成するまで新しいアプリは一覧へ表示されない。
- Clean Tasksは正式公開作品ではないため、後から一覧データを整理する必要がある。

## テスト・検証内容

- 公開済みアプリだけが公開用一覧へ含まれることをunit testで確認する。
- Clean Tasksの○○DDが「学習DD」であることをunit testで確認する。
- Prettier、ESLint、TypeScript、Vitest、Next.js production build。
- desktopとmobileでカード内の文字とボタンが重ならないことを確認する。

## 今後の見直し条件

- ちんちんゲームの紹介動画を公開するとき。
- Clean Tasksを公開一覧から削除するとき。
- YouTube APIやDBから公開状態を取得するとき。
- ログインやアプリのプレイ履歴を導入するとき。
