# 動画制作SOP(3日サイクル)

アプリを作ってから、YouTube動画とアプリを本番公開するまでの標準手順をまとめる。3日に1本のペースを守るため、毎サイクルの判断を減らし、抜け漏れをなくすことが目的。

方針の経緯はIssueを正とする。このガイドは決定事項を複製せず、手順として並べ直したものに留める。

- 全体計画と週次の足切り: Issue #168
- 台本テンプレ(注釈付きリファレンス台本): Issue #166
- AI音声の速度・尺・画角: Issue #165

アプリ側の公開準備、release停止、同時公開の正式な手順は`docs/guides/app-development-cycle.md`を正とする。このSOPはそこへ接続する動画側の工程表である。

## 3日サイクルの全体像

```text
D1: アプリ開発(4h)
  ↓
D2: 台本(1.5h) → AI音声(0.5h) → プレイ映像の録画
  ↓
D3: 編集 → サムネ → 公開準備 → release → YouTube公開 → Xポスト
```

各工程に時間上限を置く。上限を超えそうなときは、品質を上げる努力ではなく仕様を削る判断をする(尺を縮める、演出を減らす、アプリの機能を削る)。

各工程の実測時間を毎回記録する。週次面談(Issue #168)でこの記録を使う。

## D1: アプリ開発(上限4h)

1. `app/apps/nishida/`を写してから中身を差し替える(`docs/guides/app-development-cycle.md`の「参照実装を写してから作る」)。
2. **4hで作れないネタは選ばない。** 途中で4hを超えると分かったら、機能を削って着地させるか、そのネタを捨てて別のネタへ変える。「あと1機能」は追加しない。
3. About / Guideの枠組みまで作る。本人が書く文章(`paragraphs`など)は空けたままでよい(週次バッチで埋める。後述)。
4. `app/apps/_lib/app-links.ts`へ`preparing`で登録する。
5. MVP PRを`dev`へ向けて作り、CI成功後にsquash mergeする。

先行開発(2本週に翌週分のアプリを作っておく)の場合は、PRを作らずbranchで待機させ、`dev`へ入れるのはそのアプリ自身のサイクルのD1で行う。`dev`に未公開アプリを重ねない。

## D2: 台本・音声・録画(台本1.5h + 音声0.5h)

1. Issue #166の注釈付きリファレンス台本を横に置き、同じ構造・同じ行数感で台本を書く。
   - 定型文は一言一句コピペ。汎用YouTuberフレーズ禁止。自虐禁止。変な一言は各セクション1個。
   - 書き終わったら「各行がリファレンスのどの役割か」を指させること。指せない行は削る。
2. AI音声を生成する。速度は**×1.3固定**。行ごとの速度切り替えはしない(Issue #165)。
3. プレイ映像を録画する。**16:9横型**で録る(3分以下の縦型はShorts扱いになり広告単価が桁で下がるため)。

## D3: 編集・公開

### 編集(上限: 5h → 7月末4h → 8月末3.5h)

1. 編集テンプレのプロジェクトファイルから開始する(ゼロから組まない)。
2. 変な一言の直前または直後に一拍の無音を入れる。落とすのは速度ではなく「間」。
3. 標準尺は3〜5分。**3分着地を許容する。** 台本や無音で尺を伸ばさない。
4. 無音+BGMだけのプレイ映像区間を作らない。間延びした区間は伸ばさず切る。
5. エンディングに高評価テロップと終了画面を入れる(高評価CTAは口で言わない)。

### サムネ(上限0.5h)

サムネテンプレの差し替えだけで作る。毎回デザインしない。

### 公開準備〜同時公開

ここからは`docs/guides/app-development-cycle.md`の「5. 公開準備Issueで公開物を揃える」「6. YouTubeとアプリを同時に本番公開する」に従う。SOPとしての要点だけ再掲する:

1. 公開準備Issueの完了条件を確認する(OG画像、metadata、`app-links.ts`の`published`化、YouTube URL)。
2. `dev → main`のrelease PRを作り、CI成功後に管理者がmerge commitでmergeする。
3. Production deploymentの成功を確認してからYouTube動画を公開する。
4. 概要欄を確認する: アプリのProduction URL、引用・参考元の明記。
5. Productionのアプリroute、ホーム、`/apps`、YouTubeリンクを確認する。
6. 公開準備Issueを手動で閉じ、release停止を解除する。
7. `app-links.ts`の`xShareUrl`と同じ内容でXへポストする。

## 週次バッチ(サイクルに混ぜない人間作業)

次の作業は3日サイクルの中に混ぜず、週1回まとめて行う。

- OG画像の作成(`docs/guides/og-image-template.md`)
- About / Guideの本人の言葉(制作経緯、パッション、注意書き)を書く・確認する
- 翌週の題材決め(週次面談の中で行う。「4hで作れるか」で選別する)

## 見直し条件

- 3日サイクルを数本回して、工程や時間上限が実態と合わないと分かったとき。
- 編集の圧縮目標(7月末4h、8月末3.5h)を達成または断念したとき。
- Issue #168の週次面談で足切りラインが変更されたとき。
